# ❓ FAQ - Часто задаваемые вопросы

## Общие вопросы

### В: Какие форматы файлов поддерживаются?
**О:** MP3, WAV, FLAC, M4A. Другие форматы могут работать если установлен ffmpeg.

### В: Сколько файлов можно загрузить?
**О:** Теоретически неограниченное количество, но зависит от свободного места. Один файл максимум 100 МБ (можно изменить в коде).

### В: Можно ли использовать через интернет?
**О:** По умолчанию только в локальной сети. Для доступа из интернета используйте VPN или обратный прокси с аутентификацией.

### В: Как часто сохраняется плейлист?
**О:** Сразу после каждого добавления/удаления трека. В файл `playlist.json`.

### В: Что будет если перезагрузить роутер?
**О:** Если настроен автозапуск - приложение запустится автоматически. Плейлист восстановится из `playlist.json`.

## Установка

### В: Какая архитектура у моего Keenetic?
**О:** Подключитесь по SSH и выполните:
```bash
uname -m
# armv7l или armv7 → ARM7
# armv5l → ARM5
# aarch64 → ARM64
```

### В: Требуется ли Go для установки?
**О:** Да, только для компиляции на ПК. На роутер загружается готовый скомпилированный файл.

### В: Можно ли установить на Windows?
**О:** Приложение не поддерживает Windows напрямую. Используйте WSL2 (Windows Subsystem for Linux 2).

### В: Сколько места занимает приложение?
**О:** Исполняемый файл ~4-5 МБ. Плюс место для аудио файлов в папке `media/`.

### В: Какие прав нужны для установки?
**О:** Требуются права на запись в папку установки. Для systemd нужны права администратора.

## Использование

### В: Как изменить название трека?
**О:** Нажмите на трек в интерфейсе и используйте функцию редактирования (если реализована).

### В: Можно ли создавать несколько плейлистов?
**О:** Текущая версия использует один плейлист. Для нескольких плейлистов скопируйте установку в разные папки.

### В: Как узнать ID трека для API?
**О:** ID видно в файле `playlist.json` или через API `/api/playlist`.

### В: Максимальный размер файла?
**О:** По умолчанию 100 МБ. Можно изменить в коде (строка ~200 в keenetic-audio-player-v2.go):
```go
r.ParseMultipartForm(100 << 20) // Измените здесь (в байтах)
```

### В: Можно ли загружать папку с файлами?
**О:** Веб-интерфейс загружает файлы по одному. Используйте скрипт `audio-player.sh upload` или скопируйте напрямую в папку `media/`.

## Проблемы и решение

### В: Приложение запустилось, но интерфейс медленный
**О:** Возможные причины:
```bash
# 1. Много файлов в плейлисте
# 2. Медленное сетевое соединение
# 3. Слабый роутер

# Решение: уменьшите количество файлов в плейлисте
./audio-player.sh clear-tracks
```

### В: Звук не воспроизводится
**О:** Проверьте:
```bash
# 1. Установлен ли плеер
which ffplay
which aplay

# 2. Подключены ли динамики
# На Keenetic проверьте подключение через веб-интерфейс

# 3. Не выключен ли звук
# На Keenetic: Система → Звук
```

### В: Файлы занимают слишком много места
**О:** Используйте сжатие:
```bash
# Конвертируйте в меньший битрейт
ffmpeg -i input.mp3 -b:a 128k compressed.mp3

# Или удалите старые файлы
./audio-player.sh clear-tracks
```

### В: Приложение потребляет много памяти
**О:** Это нормально для больших плейлистов. Если проблема критична:
```bash
# Перезагрузите приложение
./audio-player.sh restart

# Или уменьшите количество файлов
```

### В: Как получить логи для отладки?
**О:** 
```bash
# В реальном времени
./audio-player.sh logs-follow

# Или сохранить в файл
tail -100 /opt/audio-player/logs/audio-player.log > debug.log
```

## Безопасность

### В: Безопасно ли давать доступ из интернета?
**О:** Нет, приложение не имеет аутентификации. Для доступа из интернета:

1. **Используйте VPN**
2. **Установите nginx с паролем**
3. **Используйте SSH туннель**

### В: Как защитить доступ к интерфейсу?
**О:** Установите nginx обратный прокси с Basic Auth:

```nginx
# /etc/nginx/sites-available/audio-player
server {
    listen 8080;
    
    auth_basic "Restricted";
    auth_basic_user_file /etc/nginx/.htpasswd;
    
    location / {
        proxy_pass http://localhost:9000;
    }
}
```

### В: Что если кто-то получит доступ?
**О:** Он может:
- Загружать/удалять файлы
- Воспроизводить звуки
- Видеть названия треков

Персональные данные не хранятся.

### В: Логируются ли действия пользователей?
**О:** Да, в файл `logs/audio-player.log`. Можно настроить логирование отдельно.

## Производительность

### В: Какая оптимальная конфигурация?
**О:** Зависит от использования:

**Для Keenetic:**
- RAM: 256+ МБ
- Место: 100+ МБ
- Сетевое соединение: 100 Мбит/с

**Для сервера:**
- RAM: 512+ МБ
- Место: 1+ ГБ
- Сетевое соединение: 1 Гбит/с

**О:**
```bash

# 2. Используйте AAC вместо MP3 (меньше процессорный вес)
# 3. Выключите ненужные функции
# 4. Используйте проводное подключение
```

### В: Как проверить использование ресурсов?
**О:**
```bash

ps aux | grep audio-player

# Сетевое соединение
nethogs -c

# Дисковое пространство
du -sh /opt/audio-player/*
```

## Интеграция

### В: Как интегрировать с Home Assistant?
**О:** Через REST API:
```yaml
automation:
  - alias: "Play alarm"
    trigger:
      platform: time
      at: "07:00:00"
    action:
      - service: script.play_audio
        data:
          track_id: "alarm_sound"

script:
  play_audio:
    sequence:
      - service: rest_command.audio_player
        data:
          url: "http://localhost:8080/api/play?id={{ track_id }}"
```

### В: Можно ли вызывать из других приложений?
**О:** Да, через REST API. Примеры на Python, JavaScript, Bash выше в документации.

## Обновления

### В: Как обновить приложение?
**О:**
```bash
# 1. Скачайте новую версию
# 2. Остановите приложение
./audio-player.sh stop

# 3. Скопируйте новый исполняемый файл
cp audio-player /opt/audio-player/

# 4. Запустите
./audio-player.sh start
```

### В: Потеряются ли мои плейлисты при обновлении?
**О:** Нет, файл `playlist.json` и медиа файлы в папке `media/` не трогаются.

### В: Какую версию Go использовать?
**О:** 1.16+ рекомендуется. Можно использовать новее.

### В: Будет ли работать на моей модели Keenetic?
**О:** Если модель поддерживает:
- SSH доступ
- /mnt/sda1 (внешнее хранилище)

То да.

### В: Как использовать встроенные динамики Keenetic?
**О:** Некоторые модели имеют встроенные динамики:
```bash
# Проверьте в веб-интерфейсе Keenetic
# Система → Звук
```

**О:** По рейтингу:
1. **ffplay** - универсальный, лучший звук
2. **aplay** - встроенный, простой
3. **mpg123** - легкий, хороший звук

### В: Может ли роутер воспроизводить FLAC?
**О:** Да, если установлен ffmpeg или соответствующий плеер.

## Linux специфика

### В: Почему говорится про systemd?
**О:** Systemd - стандартный в современных Linux дистрибутивах. Позволяет:
- Автоматический запуск
- Контроль ресурсов
- Логирование

### В: Что если нет systemd (старый Linux)?
**О:** Используйте cron или init.d скрипт из инсталлятора.

### В: Как запустить как systemd сервис?
**О:** Инсталлятор сделает это автоматически. Или вручную:
```bash
sudo cp audio-player.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable audio-player
sudo systemctl start audio-player
```
